# 普通陆地与水域素材样本

此目录供元素编辑器和地图 Demo 读取同一套原作素材、动画定义与规则数据。`elements.json` 按元素 ID 索引；`rules.json` 提供普通平地水岸的 46 行邻域表及三个动画元素引用；`water-shore-atlas.webp`（624×1140）包含 **144 张原作图片**，由 RGB555 原值与原透明信息解码，不缩放或重绘。

- `emperor-bare-land` 及 `-1`～`-7`：原作公共黄土247～254，共8张，与45张草地共用 `grass-atlas.webp`。普通陆地、道路底图及采石地外圈引用同一套定义；按世界格坐标稳定选择，`terrainVariant` 可固定外观。由四种扩为八种会改变部分旧图的外观，之后刷新、四镜头与JSON回读保持稳定。
- `emperor-grass-202`～`emperor-grass-246`：五档草地，各九种外观，共用`grass-atlas.webp`。
- `emperor-tree-927`～`emperor-tree-971`：18张普通树、18张竹类、9张共用残株外观，共用`trees-atlas.webp`（720×486）。占地均为单格，图片尺寸不决定占地。
- `emperor-rock-458`～`471`、`472`～`485`、`486`～`499`：普通石、铜矿、铁矿各14张，分别8张1×1、4张2×2、2张3×3，共用`rocks-atlas.webp`（1120×636）。逻辑占地取原作组合分支，不由图片宽度推断；四向共用图片，逐向锚点对齐整个底面。
- 草地202统一引用 `emperor-grass-202`；旧导出定义若引用 `emperor-terrain-202`，需改用此公共 ID。
- `emperor-terrain-386`～`emperor-terrain-457`：原普通水岸组的全部 72 张图片。
- `emperor-terrain-664`～`emperor-terrain-735`：水面动画所需的全部 72 张原图，单图定义保留供素材检查。

Demo的植被与岩石类别、素材池及地表/高程/道路建筑的图集加载清单统一由[`terrain-sample.js`](../../js/terrain-sample.js)维护；这是样本消费配置，不属于基础库API。

元素库共 **554 项定义**：551 项 v1 静态单图，以及共用上述图集的 3 项 v2 动画。每个动画的 `sequences.water` 都有 24 帧，四向显式引用同一序列，各向锚点仍独立。

| 动画元素 | 原图帧序 | 普通场景中的用途 |
|---|---|---|
| `emperor-water-even` | 664、666、…、710 | 普通内部水面，以及偶数外观字节的内部过渡 |
| `emperor-water-odd` | 665、667、…、711 | 奇数外观字节的内部过渡 |
| `emperor-water-deep` | 712、713、…、735 | 宽阔水域的深处 |

不能把 #664～711 按连续编号播成 48 帧。三个动画均明确设置 `frameDurationMs: 100`、`timingSource: "author"`：**100ms 是本样本作者选择的预览时长**，不是推断出的原作固定帧率。实际播放时间由页面时钟传入，不写入定义或地图。

邻域顺序和条件含义记录在规则中；条件 0 为水、1 为非水、2 为任意。QTiled 的 0、90、180、270 度对应原表列 `[1,0,3,2]`。完整图像高度为 40～58，不能统一裁成 40；锚点 `[39,height-20]` 为工具明确采用的底部菱形中心。

普通水面、过渡和深处由陆/水布局派生，不新增作者填写的水深字段。规则先检查 3×3 水域，再执行原作对应的形态修整；保留下来的内部标记还须八邻全为标记，才使用 deep 帧族。有陆地包边的 3×3 水池只有普通内部水面，4×4 水池有过渡，5×5 水池才出现中央一格深处。固定外观输入来自已有 `terrainVariant` 或工具的世界坐标哈希，初始相位不因镜头、反复预览或 JSON 存读重新抽取。

本样本的 deep 表示常态水域的派生外观，不表示数值水深或洪水模拟。

水岸邻域匹配将界外及 `null` 格视为水侧，但它们不作为实际水源，也不绘制或修改。普通水面规则不承担海滩；BEACH 与 rim 由 `beach-rules.js` 处理。洪水模拟尚未实现，高程与网络由其他 Demo 规则处理。缺少动画元素或不支持的输入会拒绝整笔候选，不退回静态图掩盖缺失。

素材来自《皇帝：龙之崛起》的 `China_Terrain.sg3` 及已有PNG，权利归原作品权利人所有。示例素材的使用不改变其权属；运行Demo不需要携带原程序。

## 三档气候地表

可选地图字段 `climate` 为 `arid`、`temperate`、`humid`；省略保留原有地表。按真实水格基础强度、岩石/采石地降低、树木/残株补充的顺序推导环境强度；空角/界外不作为来源。草地五档各九张、档内固定外观；干旱使用土坡，另两档沿用原坡面。强度/档位/图片不写入地图；树木和残株共用50起、四邻每步减10的传播，较强来源阻止覆盖。普通石、铜矿、铁矿和采石地共用原作降低规则：距真实水格至少6格（Chebyshev距离）且当前强度为正时，按世界行列顺序启动；从-10起四邻每步+20限制现值，负值钳为0，现值更低则截断、等值仍传播，上限达到100停止。空角仅作临时传播位置。此后再处理树源，不能按矿堆显示尺寸或把多个来源相加。海滩参与水源距离，沙丘参与干湿降低；未包含肥力生产和五行风水计算。

树木类别由`cell.tree`保存，支持普通树、竹类及各自静态残株。成熟普通树和竹各有外围/包围两组9图，残株共用一组9图，组内稳定选择；这是本工具的创作规则。绘制资格、冲突、清除与存读见[地图工具说明](../../../../docs/map-definition.md#成熟树木与竹类)。不模拟生长、砍伐或恢复计时。

水岸图集最初名为 `atlas.png`，后改名为 `water-shore-atlas.png`，现无损转换为 `water-shore-atlas.webp`，保留转换前完整 RGBA 和裁切。现仅保留水域和岸线；重复草地202的槽位清空，其他裁切位置不变。岩石的占地、冲突、历史及存读见[岩石与矿物](../../../../docs/map-definition.md#岩石与矿物)。

## 静态采石地

地图格以 `quarry: true` 保存采石范围；不存在时省略字段。地图编辑器使用独立“采石地”按钮，共用方形/菱形1～9格尺寸笔刷，偶数尺寸沿+x/+y锚定，允许相邻/重叠扩展；使用通用清除逐格或按可调笔刷范围移除，无修饰键擦除操作。整笔预览、取消、撤销/重做及JSON存读复用现有地图事务。环境作用按上节规则由每个采石格参与重建；不包含可采数量、开采进度或生产。

`quarry-atlas.webp`仅包含原China_Terrain.sg3记录972..977、1006..1125，共126张；外圈回退的247..254直接引用 `grass-atlas.webp` 中的8个公共黄土定义。每格单独派生图像，不创建6×6父实体。原包SHA-256为`56e9fe6bbbbdc93d28f44883bd9bd8f9cfe0198f024a5af1e4589d47319f374d`。采石地图集保留透明间隔；公共黄土第253号的46px完整高度及锚点在草地图集中保留。

`quarry-rules.js`采用原程序0x837e70/0x8380f0规则表、0x543e20的静态几何分支及现有镜头列映射[1,0,3,2]。变体由已存terrainVariant或稳定世界坐标字节决定，镜头转动不改变事实。每格须为平地；同一笔可跨互不相连的不同高度平台，不要求整笔等高。绘制可替换树木、岩石矿物、道路和失效实体，最终不与它们叠放，也不占坡面。原表无法匹配的零碎边缘使用公共黄土回退，保留采石事实与其余坑壁；这是工具的确定性显示策略，不声称复刻原作残留绘制状态。

## 环境模块边界补充

水→岩石/采石地→树木的环境派生现集中在`demo/static/js/environment-rules.js`，陆水选图、树木放置资格和格子详情消费同一结果。原作参数、扫描顺序和截断条件保持不变；不依赖素材或镜头，不扩展基础库API。该脚本须在`land-water-rules.js`之前加载。

## 海滩补充

新增 `beach-atlas.webp` 与114个 `emperor-beach-*` 单格定义：574..645 为沙岸，736..741 为沙地，742..777 为陆地/混合岸线交界。范围按消费者算式集合确定，不按下个符号起点猜长度。rules.json 的 beachRows 复用原草地交界26行；特殊水岸分支在 Demo beach-rules.js。全部原图78宽，部分带草石的图高40..58，锚点为 `[39, height - 20]`，不裁上凸像素。

该片未运行原游戏；只支持普通平地的新建记录映射，未复刻原作记录生命周期。海滩不是沙漠；与未来独立沙漠地形的衔接待证。

草沙交界只使用742～753完整原图，四镜头沿用原表；派生图集、46个派生定义和四分块选图已删除。不能直接表达的孤格、窄条、N09在笔刷候选中按目标地表整理，预览显示联动格，整笔可撤销；读取旧图不静默修改。这是工具约定，不是原作递归算法证据。礁石12组的SG索引已确认，深浅/外观/推进消费者尚未接通，未接入产品。

正式图集统一采用无损 WebP，保留完整 RGBA、透明像素 RGB、尺寸及原裁切位置；处理约定见仓库 AGENTS.md。旧元素文件引用 `.png` 图集时需同步更新为 `.webp`。

## 盐沼

`emperor-salt-marsh-869`～`877`复用既有九张 China_Land3_00296～00304 PNG，原图78×40不缩放、不重绘，四向共用裁切及锚点 `[39,20]`。正式图集 `salt-marsh-atlas.webp` 为238×124，3×3排列、单格步长80×42；采用无损 exact 编码，完整RGBA（含透明像素RGB）与九张原图逐像素相同。

地图保存 `saltMarsh: true`，普通道路覆盖显示但保留盐沼事实，清路后沿现有场景重算恢复原图；变体使用固定外观字节模9。新增门槛、环境传播与工具限制见[地图说明](../../../../docs/map-definition.md#盐沼与道路恢复)。

## 山峰

`emperor-pinnacle-1`～`4` 是四种独立外观，复用 Pinnacle_00001～00004 PNG，与 `China_Terrain.sg3` 记录1440～1443的完整 RGBA 一致。四图尺寸分别为398×520、398×544、398×468、398×475，不缩放、不重绘；`pinnacles-atlas.webp` 为1598×544，横排间隔2像素，使用无损 exact 编码。

每种外观均为占地5×5的 `sprite`，四镜头共用该外观的完整裁切。以图片高度 H 计算，0°、90°、180°、270°锚点分别为 `[39,H-100]`、`[199,H-180]`、`[359,H-100]`、`[199,H-20]`，保持图片底面与旋转后的世界占地一致。四张图不作为彼此的镜头方向。

地图用独立实体保存外观、位置与朝向，不向25个格子复制山峰字段。放置、整座清除、环境地面恢复与历史沿用现有实体和地图流程，见[山峰工具说明](../../../../docs/map-definition.md#山峰)。
